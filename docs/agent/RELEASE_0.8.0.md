# SnapIMS Next 0.8.0 — on-demand application agent

The existing AI workspace now understands SnapIMS context and uses a compact local
tool gateway to inspect inventory, batches, photographs, recognition, the complete
market library, pricing evidence/history, Shopify reviews/jobs, tasks, errors,
public settings and database health. It retrieves actual records on demand.

Choose **Chat Only**, **Read Access** or **Full Agent**. Full Agent saves reviewable
single/bulk proposals; it cannot approve them. Mixed workflows combine reviewed
metadata corrections, real sold-evidence prices, recognition, readiness and local
listing preparation in one atomic local review. Batch/task/settings/archive controls
and existing native Shopify management/publication reviews are integrated.

Tool activity, compact results, native navigation, explicit compressed-photo staging,
approved-task links, persistent operation history and token/cost details remain in
the existing workspace. Economy/Standard budgets bound context, rounds and calls.
Large searches/ranking run locally. Old attachments and later tool rounds do not
repeat image/file transmission. The model remains idle after each requested task.

No continuous AI observation, screenshots, model polling or automatic photo sends.
No raw SQL/shell/tap tools, credential access, automatic approvals or billing fallback.
Paid recognition, financial/archive changes, external uploads and live publication
retain explicit safeguards. A queued job is not reported as completed.

VersionCode10, same package/signing identity, Room9 in-place migration. Photo-inclusive
snapshot9 adds policies/traces/usage and supports legacy3–8. Existing capture,
recognition, market/import/export/backup, inventory and desktop compatibility remain.
The private market CSV and signing credentials are excluded from APK/source.

See [agent capabilities and exact limits](APPLICATION_AGENT.md), the
[implementation audit](INTEGRATION_AUDIT.md) and [executed test results](../TEST_RESULTS.md).
Physical Pixel/SIWC and real Shopify authorization/development-store acceptance are
unverified; no broker is deployed and no production data is changed.
